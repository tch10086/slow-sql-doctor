# 使用说明

这个工具做三件事：看一条 SQL 为什么慢、建议加什么索引、把优化前后的差距量出来。

下面按"从零到跑通"的顺序写。命令都在项目根目录执行。

---

## 1. 环境

- JDK 17 及以上（项目用 17 编译，21 也能跑）
- Maven 3.9+
- MySQL 8.0
- 可选：DataGrip / DBeaver，用来手工看表和执行单条 SQL

```bash
java -version
mvn -v
mysql --version
```

---

## 2. 初始化数据库

用 root 执行一次，建库和两个账号：

```bash
mysql -u root -p < db/00_init.sql
```

PowerShell 不支持 `<`，可以登录后执行：

```sql
source db/00_init.sql;
```

建表：

```bash
mysql -u sqlquery -p slow_sql_lab < db/01_schema.sql
```

两张表：

- `t_user`：10 万行，`city`、`username` 有索引
- `t_order`：100 万行，`user_id`、`order_no` 有索引，`create_time` 故意不建索引，`status` 低区分度

验证：

```sql
USE slow_sql_lab;
SHOW TABLES;
SELECT COUNT(*) FROM t_order;
```

如果报 `Unknown database`，说明 `00_init.sql` 没执行成功；如果报 `No database selected`，先 `USE slow_sql_lab;`。

## 3. 造数

```bash
mvn -q -DskipTests compile exec:java -Dexec.mainClass=com.sqlquery.tools.SeedData
```

成功会看到：

```text
users done: ... ms
orders: 100000
...
orders done: ... ms
```

数据分布是 80% 订单分给 2 万热用户，20% 分给 8 万冷用户。`COUNT(DISTINCT user_id)/COUNT(*)` 大约 0.09。

> 造数前可以先删掉 `t_order` 的二级索引，插完再加回来，会快很多。具体命令在 `db/01_schema.sql` 的注释里。

---

## 4. 采集基线

```bash
mvn -q -DskipTests compile exec:java -Dexec.mainClass=com.sqlquery.tools.BaselineRunner
```

它会跑 16 条 SQL，把结果写进 `docs/baseline.csv`：

- `type` / `key` / `rows` / `extra`：来自 `EXPLAIN`
- `median_ms`：预热 2 次、正式 3 次的中位数
- `handler_reads`：`Handler_read_*` 前后差值

Q12 是笛卡尔积，程序只对它执行 `EXPLAIN`，不会真跑。

---

## 5. 跑诊断

先打包：

```bash
mvn -q -DskipTests package
```

### 默认 SQL

```bash
java -jar target/slow-sql-doctor-1.0.0.jar
```

默认诊断 Q01。

### 指定 SQL

```bash
java -jar target/slow-sql-doctor-1.0.0.jar "SELECT * FROM t_order WHERE status = 3"
```

### 打印 EXPLAIN JSON

```bash
java -jar target/slow-sql-doctor-1.0.0.jar -v "SELECT * FROM t_order WHERE status = 3"
```

### 只测耗时

```bash
java -jar target/slow-sql-doctor-1.0.0.jar bench "SELECT * FROM t_order WHERE status = 3"
```

输出：

```text
median=282 ms, handler_reads=1000003, rows=166000
```

### 慢日志聚合

```bash
java -jar target/slow-sql-doctor-1.0.0.jar slowlog /path/to/slow.log
```

按指纹聚合，按总耗时排序，打印前 20 类。

## 6. 输出怎么读

一次诊断会打印四段：

```text
--- PLAN ---
query_cost=31.27, filesort=true, temporary=false
- t_order type=ref key=idx_user_id rows=40 filtered=100.0 used=[...]

--- ISSUES ---
[MEDIUM] R07 回表
  evidence: t_order: SELECT * 需要回表取整行
  advice:   考虑覆盖索引...

--- INDEX SUGGESTIONS ---
ALTER TABLE `t_order` ADD INDEX `idx_user_id_create_time` (`user_id`, `create_time`);
  reason: 等值列 [user_id]；排序列 [create_time]
  risk:   ...

measure: median=0 ms, handler_reads=41, rows=20
report: ...\docs\reports\q-xxxx.md
```

- `PLAN`：`type` 越靠后越差（`ALL` 是全表扫），`key` 是实际用的索引，`rows` 是估算。
- `ISSUES`：规则命中，`evidence` 是证据，`advice` 是建议。
- `INDEX SUGGESTIONS`：只生成 DDL，**不会自动执行**。`risk` 里会提示写放大、冗余索引。
- `measure`：中位耗时、Handler 差值、返回行数。
- `report`：Markdown 报告路径，同目录还有一份 HTML。

## 7. 报告

每次诊断会在 `docs/reports/` 下生成一对文件：

```text
q-<hash>-<timestamp>.md
q-<hash>-<timestamp>.html
```

HTML 直接用浏览器打开即可；Markdown 适合贴到 PR/文档里。

仓库里保留了一份示例：`docs/reports/sample-q01.html`。

mvn test

## 10. 常见问题

**PowerShell 里 `mysql ... < file.sql` 报错**

PowerShell 不支持 `<`。登录后用 `source file.sql;`，或者改用 Git Bash。

**控制台中文乱码**

先执行 `chcp 65001`，或在 Windows Terminal 里运行。

**连不上数据库**

检查 MySQL 服务、端口 3306、`sqlquery` 密码。默认配置可以用环境变量覆盖：

```text
SQLQUERY_DB_URL
SQLQUERY_DB_USER
SQLQUERY_DB_PASSWORD
SQLQUERY_DB_POOL_SIZE
```

**Q12 为什么没有耗时**

它是笛卡尔积，工具只做 `EXPLAIN`，不执行。

**诊断结果里没有索引建议**

可能已经有相同/前缀索引，或者查询没有可用的过滤/排序列，或者命中了笛卡尔积被跳过。

**报告目录是空的**

报告写在"运行时工作目录"下。用 `java -jar` 时要在项目根目录执行；IDEA 里检查 Run Configuration 的 working directory。

```bash

mysql -u root -p < db/00_init.sql

# 测试 / 打包
mvn test
mvn -q -DskipTests package

# 诊断
java -jar target/slow-sql-doctor-1.0.0.jar
java -jar target/slow-sql-doctor-1.0.0.jar "SELECT ..."
java -jar target/slow-sql-doctor-1.0.0.jar -v "SELECT ..."
java -jar target/slow-sql-doctor-1.0.0.jar bench "SELECT ..."
java -jar target/slow-sql-doctor-1.0.0.jar slowlog slow.log
```
