## 0. 技术栈地图（先看这张表）

这个项目涉及的每一项技术，以及它可能在哪一节被问：

| 技术 | 项目里用在哪 | 问题章节 | 面试权重 |
|---|---|---|---|
| Java 17/21（集合、泛型、异常、Stream、record、线程池） | 全部代码 | §2 | 高 |
| Maven（生命周期、依赖、插件、fat jar） | 构建与打包 | §4 | 中 |
| JUnit 5（参数化、fixture、断言） | 规则引擎测试 | §5 | 中 |
| JDBC（PreparedStatement、批处理、事务、超时） | 执行 SQL、造数 | §3 | 高 |
| HikariCP（池参数、泄漏、失效检测） | 连接管理 | §3 | 中 |
| MySQL 8.0 / InnoDB（页、redo/undo、buffer pool） | 被测数据库 | §7 | 高 |
| B+ 树与索引（聚簇/二级/联合/覆盖/下推） | 规则与建议的核心依据 | §8 | 极高 |
| 优化器与 EXPLAIN（成本、type、Extra、统计信息） | 执行计划采集与解读 | §9 | 极高 |
| 慢查询日志 / performance_schema | 批量模式 | §10 | 中 |
| 事务、锁、MVCC | 面试延伸（很可能从"加索引"拐过去） | §11 | 高 |
| JSqlParser / AST | 规则判定、SQL 归一化 | §6 | 高 |
| Jackson（树模型解析 JSON） | 解析 EXPLAIN JSON | 附录 A | 低 |
| HttpServer（可选 Web） | 网页界面 | 附录 A | 低 |
| SLF4J / Logback | 日志 | 附录 A | 低 |
| Git / GitHub | 版本管理与交付 | §4 | 低 |
| HTTP / JSON API（可选） | Web 接口 | 附录 A | 低 |

> 面试官不会按这张表顺序问。他的路径通常是：
> **项目 → 索引 → 执行计划 → 事务/锁 → Java 基础 → 场景题**。
> 所以 §8、§9 必须最熟，§2、§11 不能崩。

## 附录 B：一页纸复习卡（面试当天看）

**项目一句话**：输入 SQL → AST 特征 + EXPLAIN JSON + Handler_read → 规则引擎 → 索引建议 → 前后对比报告。

**四个数字**：数据量（100 万行）、识别准确率（X%）、耗时降幅（Y%）、扫描行数降幅（Z%）。

**三条主线**：
1. 为什么慢：访问类型 + 索引 + 排序/临时表。
2. 怎么改：等值 → 范围 → 排序；覆盖；别过度索引。
3. 怎么证明：同连接、预热、3 次中位数、估算与实测并列。

**三个局限**（主动说）：只支持 SELECT/PlainSelect；`rows` 是估算；热缓存测量。

**三个"我不知道"的安全回答**：
- "这块我做到 X，再往下是 Y，我还没实现。"
- "这个结论我只在自己的数据量上验证过，生产环境要重新测。"
- "我不确定，但我会先看 `EXPLAIN` 和 `optimizer_trace` 再下结论。"
